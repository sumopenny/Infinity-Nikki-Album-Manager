# 衣橱云同步：共享账号、独立快照

日期：2026-10-22。状态：实施决定；实际远程迁移与部署结果单独报告。

## 背景

现有共鸣具有账号、HttpOnly 会话、版本覆盖与幂等回执。衣橱已有 IndexedDB 快照、`imported` 空数据语义和展示区服。用户确认共用账号、独立手动操作、整份覆盖、区服随存档恢复，并允许有效的 0 件存档同步。

## 决定

1. 共用认证、Cookie 和请求基础能力；共鸣与衣橱业务模块互不依赖。现有共鸣 API、Cookie、请求头和兼容导出保留。
2. 在 RESONANCE_DB 追加衣橱状态、快照、记录表，独立版本和回执。不迁移已有共鸣表，不引入第二套账号库。
3. 衣橱 schema 是纯模块，服务端不加载图鉴或浏览器存储。上传未知合法 ID，保留 owned=false 和旧来源。
4. 摘要随版本提交；预览不拉取全部云端数据，下载确认时读取完整快照并核对版本。
5. 本地无副作用读取与云端规范化分开；本地缺失区服不因上传副本补齐而制造虚假冲突。服务端版本控制并发，设备时间仅用于展示。
6. 有效 0 件仍是当前快照；无云存档使用空指针和 data:null。清空本地不是删除云端。
7. 提交与后续清理解耦。响应丢失复用固定请求；提交成功后的清理异常保留成功语义，并在后续维护重试。
8. 共享认证表单与模态外壳，衣橱同步状态放在独立 composable；不创建通用同步框架，不引入新的状态管理依赖。

## 替代方案与取舍

- 两份数据整包同步会令单模块操作误覆盖另一模块，独立账号增加使用和维护成本，因此采用共享认证和独立业务表。
- 把既有共鸣表重构为通用多模块表能减少部分结构重复，但扩大迁移与回退范围；本次选择追加迁移。
- 全量预览简单，但上传和删除不需要完整记录；摘要接口增加少量协议，减少传输和解析成本。
- 自动同步、合并和按时间覆盖会引入用户未确认的冲突语义；第一版保持手动完整覆盖。
- 暂存和回执增加存储成本，以换取中断恢复和并发安全。机会清理没有后台定时成本，但不保证到期立即删除。

## 验证边界

用现有 D1 集成测试验证旧账号迁移、模块隔离、并发、重试、空存档及清理失败；组件测试覆盖区服、本地冲突、同请求重试与共享会话竞态。本地实际使用通过远程代理访问 Cloudflare D1；测试模拟数据库不充当运行时后端。部署与回退见 [云同步文档](../resonance-cloud.md)。
